# Контракт ленты архива tgcli, версия 1

**Статус:** проект контракта. Указанные ниже команды пока не существуют.
Их реализация принадлежит `~/code/tgcli`, а не этому репозиторию.

## Операции

- `snapshot(account)` возвращает все видимые записи локального архива и
  непрозрачный курсор `W` одного согласованного снимка.
- `changes(account, after=W, limit=N)` возвращает события строго после `W`
  в возрастающем порядке и следующий курсор. Пустой результат сохраняет
  текущий курсор. Повтор запроса с тем же курсором безопасен.
- Приёмник сначала обрабатывает снимок, затем ленту после `W`. В ленту
  попадают также изменения, возникшие во время обработки снимка.
- Операции доступны без второй MTProto-сессии и не меняют архив. Формат
  выдачи — JSONL либо эквивалентный поток с теми же полями и гарантиями.

## Событие

```json
{
  "version": 1,
  "cursor": "opaque-monotonic-token",
  "accountId": "telegram-user-id",
  "type": "upsert",
  "chatId": "synthetic-chat-id",
  "topicId": null,
  "messageId": 42,
  "sourceRef": "tgcli://account/chat/message",
  "messageDate": "2026-10-05T09:00:00Z",
  "observedAt": "2026-10-05T09:00:03Z",
  "text": "Синтетический пример",
  "media": []
}
```

`type` принимает `upsert` и `delete`. Для `delete` обязательны `accountId`,
`chatId`, `messageId` и `cursor`; текста в событии нет. `sourceRef` — стабильная
ссылка на оригинал в tgcli; публичный Telegram URL добавляется только когда
он действительно существует. Пара
`(accountId, chatId, messageId)` идентифицирует оригинал. Курсор определяет
порядок изменений в одном источнике, а `messageDate` — время сообщения;
это разные величины. Поля `text` и `media` при `upsert` отражают текущую
сохранённую версию. Содержимое вложенных файлов в v1 не передаётся.

## Гарантии

1. Вставка, правка и удаление архивного сообщения создают событие **в одной
   транзакции** с изменением сообщения. Правка даёт `upsert`, удаление —
   `delete`; для удаления личного чата tgcli сначала устанавливает точный
   `chatId` каждой удаляемой строки.
2. На повторе потребитель может получить то же событие. Запись в OpenViking
   и локальная фиксация курсора должны быть идемпотентны. Курсор сохраняется
   только после проверки обработки всей полученной партии.
3. Время сообщения или ID не используются как курсор: поздняя правка старого
   сообщения иначе потеряется.
4. При недоступной истории изменений или повреждённом курсоре потребитель
   останавливается и требует нового согласованного снимка; он не объявляет
   индекс актуальным.
5. Курсор относится к одному аккаунту и одному логическому источнику. Формат
   и срок хранения событий версионируются; до появления подтверждённого
   потребителя события не очищаются.

## Покрытие

Снимок включает лишь уже архивированные сообщения. Вместе с ним tgcli
должен отдавать диагностический статус: число известных чатов, число чатов
с отключённой синхронизацией, состояние фоновых задач и момент последнего
успешного приёма. Такой статус не доказывает полноту истории, но позволяет
не выдавать частичный индекс за полный.
