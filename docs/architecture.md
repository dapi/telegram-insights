# Архитектура

## Цель

Покрыть весь доступный tgcli архив личного Telegram: каналы, группы и личные
диалоги. Первые пользовательские сценарии — ежедневная сводка по подпискам и
ответы, собранные из нескольких переписок. Физический host и расписание пока
не выбраны.

```text
Telegram → tgcli → PostgreSQL / исходная схема
                         ├→ read-only представление → аналитическая схема + pgvector
                         └← проверка оригиналов ← сводка / ответ со ссылками
```

## Ответственность

1. **tgcli** владеет исходными таблицами PostgreSQL, Telegram-сессией и
   read-only представлением для начального прохода и новых сообщений.
   Внешний потребитель не меняет исходные таблицы и не открывает вторую
   Telegram-сессию.
2. **Индексатор** идемпотентно превращает сообщения в небольшие контекстные
   фрагменты. Фрагмент не пересекает границу чата или темы и хранит точный
   перечень ID сообщений. После подтверждённой записи в аналитическую схему он
   сохраняет курсор обработки. В первой версии правки и удаления не
   синхронизируются; это явное ограничение актуальности проекции.
3. **Поиск** объединяет полнотекстовых и векторных кандидатов PostgreSQL.
   Он дочитывает соседние сообщения из оригинала и проверяет, что
   кандидаты не удалены и не устарели. Ответы содержат ссылки на конкретные
   сообщения; противоречия и недостаток свидетельств отмечаются явно.
4. **Сводка** отбирает новые сюжеты за период, сводит повторные публикации,
   указывает источники и отделяет сообщение автора от вывода системы.

## Полнота и конфиденциальность

- «Весь Telegram» означает весь архив, который tgcli действительно может
  получить, а не обещание полноты серверной истории Telegram. Покрытие
  проверяется отдельно: число чатов, отключённая синхронизация, ошибки
  фоновых задач и возраст последних сообщений.
- Аналитическая схема PostgreSQL хранит копию личных сообщений и embeddings.
  tgcli и аналитический процесс получают разные роли с минимальными правами.
  Модельный маршрут и копирование данных проверяются до фактического импорта.
- Два архива одного аккаунта нельзя слепо складывать: для каждого аккаунта
  выбирается один логический источник ленты либо отдельно проектируется
  сверка версий. Конкретный host этим документом не назначается.
- В Git не попадают сообщения, индексы, embeddings или реальные сводки.

## Ограничение текущего tgcli

tgcli сейчас работает на SQLite. Решение о переводе на PostgreSQL записано в
ADR-0002 репозитория tgcli; перенос ещё не выполнен. Первая аналитическая
версия будет использовать монотонную последовательность вставок и пока не
отслеживать правки и удаления. Контракт описан в
[postgresql-source.md](postgresql-source.md).
