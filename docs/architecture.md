# Архитектура

## Цель

Покрыть весь доступный tgcli архив личного Telegram: каналы, группы и личные
диалоги. Первые пользовательские сценарии — ежедневная сводка по подпискам и
ответы, собранные из нескольких переписок. Физический host и расписание пока
не выбраны.

```text
Telegram → tgcli (оригинал) → лента изменений → Telegram Insights
                                              ├→ OpenViking (поисковая копия)
                                              └→ сводка / ответ со ссылками
                         ↑                            │
                         └──── проверка оригиналов ────┘
```

## Ответственность

1. **tgcli** хранит сообщения и отдаёт согласованный снимок архива и
   последовательную ленту вставок, правок и удалений. Внешний потребитель не
   меняет SQLite tgcli и не открывает вторую Telegram-сессию.
2. **Индексатор** идемпотентно превращает сообщения в небольшие контекстные
   фрагменты. Фрагмент не пересекает границу чата или темы и хранит точный
   перечень ID сообщений. После подтверждённой записи в OpenViking он
   сохраняет курсор обработки. Правка или удаление перестраивает затронутые
   фрагменты.
3. **Поиск** объединяет лексические кандидаты из tgcli и смысловые кандидаты
   OpenViking. Он дочитывает соседние сообщения из оригинала и проверяет, что
   кандидаты не удалены и не устарели. Ответы содержат ссылки на конкретные
   сообщения; противоречия и недостаток свидетельств отмечаются явно.
4. **Сводка** отбирает новые сюжеты за период, сводит повторные публикации,
   указывает источники и отделяет сообщение автора от вывода системы.

## Полнота и конфиденциальность

- «Весь Telegram» означает весь архив, который tgcli действительно может
  получить, а не обещание полноты серверной истории Telegram. Покрытие
  проверяется отдельно: число чатов, отключённая синхронизация, ошибки
  фоновых задач и возраст последних сообщений.
- Индекс размещается только в приватной пользовательской области OpenViking.
  Это всё равно копия личных сообщений и их обработка действующим модельным
  маршрутом; фактический импорт требует отдельного запуска после проверки
  этого потока данных.
- Два архива одного аккаунта нельзя слепо складывать: для каждого аккаунта
  выбирается один логический источник ленты либо отдельно проектируется
  сверка версий. Конкретный host этим документом не назначается.
- В Git не попадают сообщения, индексы, embeddings или реальные сводки.

## Ограничение текущего tgcli

Архив хранит текущие сообщения, но пока не предоставляет внешнюю ленту
изменений. При удалении строка стирается; отдельного курсора правки сообщения
нет. Поэтому опрос таблицы `messages` по времени не гарантирует перенос
правок и удалений. Контракт нужной ленты описан в [tgcli-feed.md](tgcli-feed.md).
