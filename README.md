# Telegram Insights

Приватный архив личного Telegram с поиском по смыслу, ответами по нескольким
перепискам и ежедневными сводками. Основное хранилище — PostgreSQL, поисковый
индекс — pgvector. По умолчанию загружается доступная история всех облачных
чатов (личных, групп и каналов) за последние 14 суток, начиная с новых
сообщений; новые сообщения принимаются непрерывно.

## Зачем это нужно

Telegram хорошо доставляет сообщения, но плохо отвечает на вопросы «что
было?»: встроенный поиск ищет по словам в одном чате, а решения, ссылки и
договорённости разбросаны по десяткам переписок. Telegram Insights держит
собственную копию переписки и позволяет работать с ней как с базой знаний —
вручную из терминала или через AI-агента.

### Сценарии

- **Утренний обзор вместо листания чатов.** `digest` собирает сюжеты за сутки
  по каналам, группам и личным перепискам, сводит повторные публикации и даёт
  ссылку на каждый источник.
- **«Что мы решили?»** Найти решение по релизу, договору или встрече, даже
  если формулировка в чате была другой: поиск гибридный — по смыслу и по
  словам.
- **Ответ из нескольких чатов.** `ask` собирает ответ из разных переписок,
  указывает источники, противоречия и пробелы в покрытии архива.
- **Найти ссылку, файл или цифру.** «Кто присылал ссылку на тот сервис»,
  «какую сумму называли в группе подрядчиков» — с фильтром по чату и датам.
- **Восстановить контекст.** Открыть найденное сообщение вместе с соседними,
  чтобы не цитировать фразу вырванной из разговора.
- **Память для AI-агента.** Агент (Claude Code, Codex и др.) через MCP-сервер
  или CLI-skill отвечает на вопросы по истории Telegram только на чтение —
  без доступа к отправке сообщений.
- **Подготовка к встрече или звонку.** Быстро собрать всё, что обсуждалось с
  человеком или командой за последние дни.

## Примеры

```sh
# Что есть в архиве: покрытие, свежесть, отставание индекса
telegram-insights status

# Поиск по всем чатам — по смыслу и по словам
telegram-insights search "что решили по релизу" --limit 8
telegram-insights search "договор с площадкой" --from 2026-10-01 --to 2026-10-05

# Поиск внутри одного чата
telegram-insights chats "Команда проекта"            # узнать chat_id
telegram-insights search "оплата" --chat <chat_id>

# Сообщение с контекстом по ссылке из результатов поиска
telegram-insights context tgi:<chat_id>/<message_id> --before 10 --after 10

# Ответ на вопрос по нескольким перепискам, с источниками
telegram-insights ask "какие сроки называли по запуску и кто их подтвердил?"

# Черновик ежедневной сводки в Markdown
telegram-insights digest
```

У каждого найденного сообщения есть `ref` вида `tgi:<chat_id>/<message_id>`, а
у сообщений каналов и супергрупп — ещё и ссылка `t.me`. Команды поиска
поддерживают `--json` для скриптов и агентов.

### Доступ с другого компьютера

CLI для чтения работает локально или удалённо — через MCP поверх SSH:

```sh
telegram-insights --remote <ssh-host> config --init   # запомнить один раз
telegram-insights search "что обсуждали вчера"
```

Для агентов есть read-only MCP-сервер (`archive_status`, `find_chats`,
`search_messages`, `get_message_context`) и skill
[skills/telegram-insights](skills/telegram-insights/SKILL.md).

## Как устроено

```text
Telegram → приём и дозагрузка → PostgreSQL (архив)
                                 └→ индекс pgvector → поиск / ответ / сводка со ссылками
```

- Архив в PostgreSQL — источник истины; поисковый индекс — производная копия.
- Загрузка соблюдает `FLOOD_WAIT`, сохраняет checkpoint и продолжается после
  перезапуска без дублей.
- Покрытие наблюдаемо по каждому чату: «загружено», «загружается», «ожидание
  лимита», «ошибка», «недоступно».
- Embeddings и ответы строятся локальной моделью (Ollama).

## Ограничения v1

- Правки и удаления сообщений не синхронизируются: архив хранит первую
  полученную версию.
- Секретные чаты и недоступная на сервере история не архивируются.
- Реальные сообщения, embeddings и сводки никогда не попадают в Git.
